# Unity 6000 integration

Agreed design for the maintained `unity-6000` branch, based on Spire 4.7.1.
The generated implementation uses active-variant payloads, owned nested
snapshots, explicit reconstruction, and per-union property drawers. The prototype
results below explain the native Unity behavior that shaped the implementation.

The follow-up copy probe confirmed that a shared mutable payload corrupts
divergent copies. Detaching the cache before a runtime mutation passed repeated
saves and a variant change. Automatic child preparation from the parent callback
also passed repeated saves. Closed generic `int`/`string` payloads and a standalone
drawer targeting the open generic definition passed Unity serialization and
type discovery. These cases now define the implementation regression tests.

## Target

- `main` retains the normal NuGet/Roslyn 5 build. Unity changes live on
  `unity-6000`; shared fixes can move between branches.
- Initial runtime support: Mono. Initial validation editor: Unity 6000.5.6f1.
  Earlier Unity 6000 minors require their own compiler verification.
- The installed 6000.5.6f1 compiler reports `4.10.0-3.25064.8`; target its Roslyn
  4.10 dependency set. The source-generator manual's 4.3 wording does not match
  this installed host.
- Rider is the supported IDE. Retain CodeFixes as IDE tooling and verify their
  discovery/execution in Rider separately from Unity compiler loading.
- Ship the Spire runtime, analyzer, and PatternAnalysis helper with Unity plugin
  metadata. Do not ship competing Roslyn/Workspaces/compiler-host assemblies.
  The local UPM package is built by `tools/build-unity-package.py`. Release
  automation remains a separate packaging decision.
- Support configuration without NuGet `.props`; retain the existing MSBuild
  configuration path where applicable.

## Serialization contract

The user enables serialization once on the union:

```cs
[Serializable]
[DiscriminatedUnion]
public partial struct SomeUnion
{
    // Variant declarations
}
```

- Detect the actual `System.SerializableAttribute` on the complete union symbol,
  including aliases and other partial declarations. Do not add the attribute or
  introduce a serialization boolean on `DiscriminatedUnionAttribute`.
- Serialized struct unions default to Additive. Omitted/Auto layout selects
  Additive, taking precedence over an inherited default. Explicit BoxedFields,
  BoxedTuple, UnsafeOverlap, and Overlap also support serialization. UnsafeOverlap
  requires unsafe code; Overlap rejects generic unions and unions nested in
  generic containing types with SPIRE_DU005.
- Reject readonly struct declarations for this mode. Initial serialization scope
  is mutable struct unions, including generics with supported field types;
  records, record structs, and ref structs are rejected in this mode.
- Consumers use ordinary Unity field annotations. No public wrapper type, custom
  owner base class, or manually implemented owner callbacks are required.
- No Odin dependency, raw-memory encoding, or unsafe serialization.

## Stored representation

Keep the selected layout's runtime fields, but explicitly exclude them from serialization,
including compiler-generated backing fields. Omitting `[SerializeField]` alone
does not exclude private fields during script reloads.

Persist a mutable `[SerializeField]` discriminator and one private
`[SerializeReference]` payload. Generate a serializable payload base class and a
concrete, typed payload class for each variant. Only the active variant's payload
is stored. Payload fields follow native Unity serialization rules; report
unsupported payloads rather than silently dropping declared variant data.

`[SerializeField] List<object>` is not a heterogeneous serialization mechanism.
Managed-reference lists also exclude boxed value types and Unity objects as
elements. Typed fields inside a generated payload retain the information Unity
needs to serialize supported values and Unity object references.

Generate `ISerializationCallbackReceiver` implementation on the union:

- `OnBeforeSerialize`: refresh the active payload from the runtime union.
- `OnAfterDeserialize`: reconstruct the runtime union through its factory, reset
  inactive runtime storage, and retain the serialized payload for Inspector use.
- Callbacks operate only on owned data; do not invoke general Unity APIs or
  depend on another object's callback having already run.

Nested unions prepare the child's serialized state before parent capture and
refresh owned, matching payloads in place during callbacks. Ownership stamps and
cache detachment keep divergent copies independent. Native regression tests
cover repeated saves, variant changes, copied values, aliased child payloads,
and nested arrays, lists, inherited private fields, and generic helpers.

Generated runtime init accessors must detach the cached payload, including
internal slot accessors. Factory-created values start with independent caches.
Preparing nested data must preserve the runtime fields and create owned
serialized snapshots; callbacks then update matching snapshot types in place.
Cross-assembly and composite-field support may use hidden generated/runtime
bridge methods. Any such bridge operates on managed data only and does not call
general Unity APIs from serialization callbacks.

Initial field policy follows native Unity value serialization: supported
primitives, enums no wider than 32 bits, Unity native values/object references,
serializable concrete classes/structs, and one-dimensional arrays or `List<T>`.
Reject dictionaries, multilevel containers, nullable value types, tuples,
unsupported System values, pointers, and polymorphic object/interface/abstract
variant fields. A generic type parameter is permitted; known unsupported closed
arguments in the consumer compilation must be diagnosed. External/dynamic
constructed arguments remain subject to the same native field contract.

Known discriminators with missing/mismatched payloads reconstruct that variant
with default fields. Unknown discriminators retain the raw invalid discriminator
with default runtime storage. Malformed serialized values must not throw during
callback reconstruction. Selecting a different variant creates default fields
for the newly selected variant and discards stale inactive data.

The discriminator and payload must describe the same variant. Rename/reorder
migration is not provided by the initial implementation; changes to variant
order or generated payload names can invalidate existing serialized assets.
Serialized size and allocation costs must be measured: eliminating inactive
fields does not guarantee a smaller result for every union.

## Inspector

- Generate a per-type `CustomPropertyDrawer` alongside the union, guarded by
  `UNITY_EDITOR`. No physical `Editor` source folder is required.
- Implement `CreatePropertyGUI`, `OnGUI`, and `GetPropertyHeight` for UI Toolkit
  and IMGUI consumers.
- Show the variant selector and active payload fields.
- Prefer constructing and assigning a replacement union through its factory.
  Keep its serialized snapshot consistent with the replacement.
- Whole-value `SerializedProperty.boxedValue` assignment and Undo/Redo passed the
  prototype. Its getter did not reconstruct the complete runtime union. Read
  through the actual owner field or explicitly reconstruct from the discriminator
  and managed-reference payload; both approaches passed for an ordinary field.
  Generated drawer tests also cover array/list elements and nested paths.
  Direct owner-field assignment is an alternative, with nested struct write-back,
  Undo, and prefab overrides handled explicitly.
- Do not assume `boxedValue` transfers nonserialized runtime fields or that
  `OnAfterDeserialize` runs for every Inspector edit/Undo. Establish actual Unity
  behavior before choosing the assignment path.

## Validation and implementation order

1. Probe the accepted storage shape in an isolated, real Unity project: asset
   save/unload/reload; object references; fields, arrays, lists, and nested structs;
   callback write-back; prepared/unprepared whole-value assignments; payload-only
   edits; Undo/Redo; and active-only persisted data. Record negative observations.
2. Compile the Unity analyzer/helper closure against Roslyn 4.10 and inspect its
   emitted assembly references. Validate CodeFixes in Rider.
3. Write generator snapshots and real Unity integration tests before implementing
   serialization and drawers. Include semantic attribute detection, layout
   restrictions/readonly declarations, unsupported fields, and name collisions.
4. Verify Editor import/reimport, actual drawer interaction in both UI systems,
   multi-object editing, prefab override/revert behavior, script reload, Play Mode,
   and a Mono player. Roslyn tests alone are not Unity runtime evidence.
5. Finalize Unity packaging/configuration, documentation, and release automation.

Existing factory/getter/init/deconstruction behavior remains the runtime API.
Inspector variant-switch retention/reset policy and serialization schema
migration are documented above. IL2CPP remains outside the initial target.

## Prototype results

The isolated project is `tmp/unity-serialization-probe/`. It uses real Unity
assets, `SerializedObject`, managed references, and Undo; it is not generated
Spire code and does not exercise a rendered drawer. The first run completed all
11 scenarios with nine passes and two failures. Detailed values and callback
traces are in `probe-results-initial.json` in that directory.

| Behavior | First run |
|---|---|
| Asset save/unload/reload and Unity object references | Pass |
| Array/list elements and a union inside an ordinary struct | Pass |
| Whole-value assignment, with and without a prepared snapshot | Pass |
| Payload-only Inspector data edit and immediate runtime value | Pass |
| Whole-value assignment Undo/Redo; direct owner assignment Undo/Redo | Pass |
| Persisting only the active payload | Pass |
| Reading a complete union with `boxedValue` | Fail: returned an Empty runtime value |
| A child union inside a parent union's managed-reference payload | Fail: child became Empty after reload |

The nested failure also produced Unity's `m_WriteObjectAccumulator.empty()`
serialization assertion. A follow-up run preserved both original failures and
added four controls: 11 passes and four failures across 15 scenarios, with no
unsupported-API observations. Results are in `probe-results.json`.

| Follow-up control | Result |
|---|---|
| Owner field read and explicit discriminator/payload reconstruction | Pass; `boxedValue` still returned Empty |
| Prepare the child before parent capture, then allocate fresh callback payloads | Fail |
| Reuse the parent payload without preparing/reusing the child's payload | Fail |
| Prepare the child and refresh same-type parent/child payloads in place | Pass; exact child values and Unity object reference survived reload |

The successful nested control produced no serialization assertion in its log
segment. It does not establish correctness for repeated saves, copies, variant
changes, callback cycles, or deeper nesting. The original failed cases remain
in the probe; a nonzero editor exit is expected for this diagnostic run.

Run from the repository root with the installed Editor:

```sh
timeout --kill-after=15s 240s /home/houtamelo/Unity/Hub/Editor/6000.5.6f1/Editor/Unity \
  -batchmode -quit -nographics -projectPath "$PWD/tmp/unity-serialization-probe" \
  -executeMethod SpireSerializationProbe.Run \
  -logFile "$PWD/tmp/unity-serialization-probe/unity-probe-controls.log"
```

Editor startup also aborted once in the Linux named-pipe implementation before
the entrypoint ran. A subsequent traced launch reached the entrypoint. Treat
that as an intermittent startup problem, not as a serialization-test result or
a proven fix from changing file descriptor limits.

## Generated implementation validation

Serialization supports explicit `BoxedFields`, `BoxedTuple`, `UnsafeOverlap`, and
`Overlap`. Omitted/Auto layout keeps the
existing Additive selection. Serialization remains an independent typed payload
projection: capture through variant getters and restore through factories. Each
layout supplies runtime-field exclusion, constructor initialization, cache
detachment, and reset hooks. `Overlap` preserves runtime offsets and appends the
payload and owner references after the runtime storage at aligned offsets.
Mutable-struct and native field restrictions remain. Every serializable layout
contains managed references; raw runtime bytes are never the serialized payload.

The repository suite passes 2,004 tests, including 671 generator tests. Unity
fixtures compile against installed engine assemblies, including the C# 9
profile; accepted generated Unity code has no nullable warnings.

The real Unity 6000.5.6f1 Editor graphics run passes 87 checks. Coverage includes
native persistence, object references, nested/copy/alias isolation, generic
helpers, both drawer APIs, invalid-kind selection, pending sibling edits,
multi-object editing, prefab overrides, Undo/Redo, physical drawer detachment,
Undo before first attachment, script reload, and Play Mode across Additive,
BoxedFields, BoxedTuple, UnsafeOverlap, and Overlap. Overlap's appended managed
references pass native Mono loading; compiled .NET behavioral tests also verify
them across forced garbage collection.

Three report entries are observations with separate checks: the Mono player is
built and run separately, and unsupported closed `object`/`Dictionary` generic
arguments are verified by Roslyn diagnostic fixtures. The Mono player loads
persisted values from all five layouts, including boxed and UnsafeOverlap generic
closures; its managed output contains only the Spire runtime DLL, with
no Spire compiler extensions or Roslyn/Workspaces assemblies.

The local UPM package contains four Spire DLLs with Unity importer metadata.
Actual Rider quick-fix discovery/execution remains unverified. IL2CPP and other
Unity minor versions remain outside the validated target.

`tools/test-unity-behavioral.py` also compiles the original runtime behavioral
declarations and assertions with Unity's compiler and executes all 129 unchanged
xUnit Facts through a Unity Test Framework adapter in Editor Mono. Five adapter
checks cover discovery, exception propagation, async execution/disposal, and
unsupported tests. The source manifest records hashes and exact expected test
names; the runner requires every original test to pass. Its C# 12 setting and
`IsExternalInit` polyfill are test-only. JSON/xUnit support DLLs are Editor-only
assets in the disposable test project; Newtonsoft.Json uses the installed
Editor's bundled assembly. The shipped package's four-DLL surface is unchanged.

The Roslyn feasibility probe passes all five checks in Editor Mono: compilation
and execution, generator output, analyzer success/failure cases, workspace
semantic models, and generated-union exhaustiveness analysis.

`tools/test-unity-harness.py` runs the complete repository harness in Unity
6000.5.6f1 on Linux. The native run passes 2,013 checks with no failures or skips:
824 analyzer, 671 generator, 339 PatternAnalysis, 27 DevTools, 14 global
configuration, 129 original runtime behavioral tests, and nine adapter checks.
Independent xUnit discovery and Unity discovery match every one of the 1,875
portable case identities, and the report contains every expected behavioral
method. Existing assertion bodies and expected snapshots are retained.

Portable test projects target netstandard2.1 conditionally; their normal .NET
targets remain available. Compiler tests retain .NET reference assemblies as
metadata inputs, while generated runtime assemblies execute against Mono.
Test-only Roslyn/Workspaces dependencies use one MSBuild dependency graph and
are imported only from its runtime manifest. Source/reference hashes and
dependency origins are recorded. The runner clears owned project inputs,
rejects conflicting DLL copies, archives prior results, and terminates its
process group on timeout. These paths have real filesystem/process regression
tests. Compiler dependencies remain outside the shipped Unity package.
The normal .NET solution and standalone global-configuration suite also pass
all 2,004 repository tests after the port.
