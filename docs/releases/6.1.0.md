# Spire 6.1.0

Spire 6.1.0 adds logical struct-union equality and authored record-struct
variants, and fixes payload captures in nullable-union switch code fixes.
All four NuGet packages use version 6.1.0.

```sh
dotnet add package Houtamelo.Spire --version 6.1.0
```

## Changes

- Ordinary struct unions implement `IEquatable<Union>` and
  `IEquatable<VariantPayload>`, with typed equality, `Equals(object?)`,
  `GetHashCode()`, and `==`/`!=` for both union/payload operand orders.
  Equality and hashing use the variant tag and active logical fields through
  `EqualityComparer<T>.Default`. Serialization payloads, caches, inactive
  storage, and extra authored record state do not participate.
- Public nested `[Variant] record struct` declarations can coexist with
  factory-method variants. The authored record replaces the generated public
  payload for that variant. Conversion extracts its positional fields and
  payload access reconstructs it; no duplicate factory or payload is generated.
- Partial record variants in serializable Unity unions receive missing
  serialization attributes automatically. SPIRE028 warns about missing
  attributes and offers fixes; SPIRE029 warns when authored positional members
  can change reconstructed values. Invalid record declarations report
  SPIRE_DU019. JSON naming and managed-reference annotations work with the
  positional schema.
- **Add missing variant arms** retains field captures when a nullable union
  also needs a `null` arm. Restricted payload gaps retain their exact patterns,
  and nullable record-union type names remain valid C#.

For example, a union can mix the two declaration forms:

```csharp
using Houtamelo.Spire;

[DiscriminatedUnion]
public partial struct Customization
{
    [Variant] public record struct Slider(int kind, int value);
    [Variant] public static partial Customization Color(uint rgb);
}

// At a call site:
Customization slider = new Customization.Slider(1, 42);
Customization color = Customization.Color(0xff00ff);
```

## Compatibility

Authored record structs require C# 10 or newer. Existing method-based variants
retain their compiler requirements. Record variants must be public and have no
type parameters of their own; their containing union may be generic. Records
without positional parameters are fieldless variants.

Union equality now follows logical active fields. Review code that relied on
default struct equality over physical storage. Record-union equality and
ref-struct union APIs retain their existing behavior.

The experimental inliner opt-in introduced in
[6.0.0](https://github.com/Houtamelo/spire_csharp_analyzers/blob/v6.0.0/docs/releases/6.0.0.md)
still applies. See the
[union guide](https://github.com/Houtamelo/spire_csharp_analyzers/blob/v6.1.0/docs/discriminated-unions.md)
for construction, matching, equality, and serialization details.

## Validation

The release suite exercises real generator output, code actions, compile/emit
pipelines, runtime behavior, and packed NuGet consumers. Unity package export
uses Unity 6000.5.6f1. This release does not extend existing player-backend
validation to authored record-struct variants.
