# Spire 6.0.0

This release adds `Houtamelo.Spire.Functional` and marks the closure inliner API
experimental. All four NuGet packages use version 6.0.0.

Install the Functional package to get Result and nullable Option operations:

```sh
dotnet add package Houtamelo.Spire.Functional --version 6.0.0
```

It targets .NET Standard 2.0 and depends on `Houtamelo.Spire`, which supplies the
runtime attributes, analyzers, source generators, and IDE code fixes. See the
[Functional API guide](../../src/Houtamelo.Spire.Functional/README.md).

The Unity package bundles both runtime DLLs and their XML documentation, plus
the offline Functional guide. The `unitypackage` command exports an importable
archive containing `Assets/Spire`; the UPM package remains available.

## Migration from 5.x

The closure inliner attributes (`[Inlinable]`, `[InlinerStruct]`), every
`IActionInliner` / `IFuncInliner` interface and `Invoke` member, and generated
forwarders and overloads are experimental and may change or be removed.
Supporting compilers report `SPIREEXP001` as an error unless you opt in:

```xml
<NoWarn>$(NoWarn);SPIREEXP001</NoWarn>
```

You can also use a scoped `#pragma warning disable SPIREEXP001` and restore it
after the declarations and calls. Other Spire diagnostics remain enabled.
This new opt-in requirement is the reason for the major version change.

Generated APIs receive the compiler annotation when `ExperimentalAttribute` is
accessible in the consuming compilation; their XML docs identify them as
experimental on every target. Older compilers, including older Unity Roslyn
versions, may ignore the annotation. See the [inliner guide](../rules/SPIRE017-SPIRE027.md).

The discriminated union and exhaustive-switch APIs retain their 5.x behavior.
Projects upgrading from 4.x should also follow the [5.0 migration guide](5.0.0.md).

## Validation

The portable suite covers real packed-package consumers, generator output,
runtime Result/Option behavior, experimental opt-in, and diagnostics that must
remain visible after opt-in. Fresh Unity 6000.5.6f1 Editor Mono import validation
exercised the Functional runtime. Player backends were not revalidated for the
new Functional API in this release.
