# Spire 6.1.1

Spire 6.1.1 adds actionable diagnostics for readonly variant serialization and
unsupported record-struct union declarations. All four packages use 6.1.1.

## Changes

- [SPIRE030](../rules/SPIRE030.md) warns when a readonly record-struct variant
  has positional data inside a Unity-serializable union. It replaces SPIRE028
  for that variant because serialization attributes cannot make readonly
  backing fields serializable. Fieldless variants remain exempt. The
  `Remove readonly from variant` fix updates all authored partial declarations.
- [SPIRE_DU020](../rules/SPIRE_DU020.md) rejects `record struct` as the outer
  union declaration and stops generation for that type, avoiding incompatible
  partial declarations and secondary compiler errors. `Remove record from union`
  converts its authored partial declarations to plain structs while preserving
  nested record variants. Nonempty positional declarations require manual
  refactoring so their data members are not discarded.
- Serializable partial readonly variants now generate the valid modifier order
  `readonly partial record struct`.
- Both fixes support declarations split across documents and Fix All, preserve
  comments and line endings, and ignore stale or generated targets.

## Compatibility and validation

Nested record-struct variant payloads and record-class unions remain supported.
Readonly variants retain their runtime conversion, matching, and equality
behavior. A serializable union's outer type must still be mutable for Unity
serialization.

The generator/code-fix suite covers actual generator diagnostics, Roslyn
workspace actions, compilation/emission, and runtime equality. Unity-specific
diagnostic checks use installed Unity references. This change does not add
native serialization or player-backend coverage for readonly payloads.
